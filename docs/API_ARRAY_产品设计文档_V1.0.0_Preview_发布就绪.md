# API ARRAY 1.0.0 Preview：发布就绪约束

## 版本

- 技术版本：`1.0.0`
- 用户展示版本：`1.0.0 Preview`
- 发布通道：`Preview`
- 唯一版本源：`src/product-version.json`

只有用户明确要求时才允许变更版本源。`Cargo.toml`、桌面 `package.json`、Tauri 配置与 UI 展示必须由版本同步/校验脚本保持一致。

## 产品语义

API ARRAY 的正式用户路径为：

1. **API 钱包**回答“我有哪些 API？”：资产、上游端点、Key、能力、预算与体检。
2. **审计直出**回答“怎样直接、受审计地使用某个钱包资产？”：一个资产可创建多个独立 Token 的本地入口。
3. **编组模式**回答“怎样把多个 API 组合为新的 API？”：项目 → 文件夹 → 编组方案。编组方案是图、出口、运行快照、文档与记录的唯一隔离边界。

`Canvas` 仅保留为内部 Rust/IPC/数据库标识；所有用户可见文案统一称为“编组方案”。

## 运行、审计与通知

- 所有本地入口仅绑定 `127.0.0.1` 或 `::1`。
- 审计只保存入口、模型、结果、延迟、重试、故障切换、Token 用量与成本估算；禁止保存正文、URL、Header、Key 和本地 Token。
- 运行记录支持安全筛选、分页读取、详情和脱敏导出；状态变化不会改变实例的稳定排序。
- 通知持久化到工作区 SQLite，按对象与状态聚合。高严重度通知可以使用 Windows 原生提醒；应用内通知中心永远保留完整脱敏摘要。
- 工作区数据损坏、网关冲突、审计降级、缺失 Secret/Token 都必须形成可定位的阻塞状态，不能静默伪装为正常。

## MSI 发布

- 使用 Tauri + WiX Toolset v3 生成 Windows x64、每用户、中文 MSI。
- 使用 `embedBootstrapper`：安装包内含 WebView2 引导程序；当系统缺少 WebView2 时仍需要网络安装运行时。
- 复用项目本地 `icon.ico` 与图标资源；无需编写单独安装器。
- Preview 不带代码签名。发布包必须附 SHA-256、已知限制和 SmartScreen 提示。
- 最终发布前必须完成：Workspace/桌面/前端测试、Debug 冒烟、MSI 安装卸载重装验证，以及已授权凭据的模型列表、最小非流式、最小流式、受控主备切换和脱敏审计验证。
